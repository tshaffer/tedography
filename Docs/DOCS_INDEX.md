# Tedography Docs Index

Brief descriptions of every Markdown file in this directory.

---

**[AI_EDIT_QUEUE.md](AI_EDIT_QUEUE.md)** — Documents the AI Edit Queue feature, which lets you mark photos for AI-assisted editing using natural-language prompts, send the queue to the Gemini API, and have Tedography save the edited results to a configured output folder automatically. Also covers the manual Export Queue option for workflows where files and prompts are copied to a folder for uploading to an external service.

**[ALBUM_TREE_COUNT_INVESTIGATION.md](ALBUM_TREE_COUNT_INVESTIGATION.md)** — Explains why album tree count labels (e.g., "143" in `08-2002 to 12-2002 (143)`) are computed entirely on the client from the in-memory `assets` array rather than stored in the database or returned from the API. Documents why counts can appear as zero even when an album is not empty, and traces through when those counts are populated and updated.

**[CLAUDE_PROJECT_SUMMARY.md](CLAUDE_PROJECT_SUMMARY.md)** — A comprehensive overview of the entire Tedography project, generated by examining the full codebase. Covers the monorepo structure and dependency direction, the core domain model, all major workflows (import, people pipeline, review UI, album tree, smart albums, maintenance), environment configuration, and the non-negotiable rules for making changes safely.

**[CURRENT_COLLECTION_USAGE.md](CURRENT_COLLECTION_USAGE.md)** — Documents every active MongoDB collection in Tedography, describing what each collection stores and which user or operator actions cause writes to it. Reflects the active model definitions in `apps/api/src/models`.

**[DUPLICATE_GROUP_UI_IMPLEMENTATION_PLAN.md](DUPLICATE_GROUP_UI_IMPLEMENTATION_PLAN.md)** — A file-oriented implementation plan that translates the agreed duplicate-group product spec into concrete code changes against the existing Tedography codebase. Covers existing code, new components, route changes, and the sequence of work.

**[DUPLICATE_GROUP_UI_SPEC.md](DUPLICATE_GROUP_UI_SPEC.md)** — The product spec for a new duplicate-group review UI, describing the intended user experience and behavior before implementation. Intentionally product-focused rather than backend-focused; describes what users will see and do rather than how the system works internally.

**[DUPLICATE_PERFORMANCE_ASSESSMENT.md](DUPLICATE_PERFORMANCE_ASSESSMENT.md)** — A code-based (not runtime benchmark) analysis of how much performance Tedography would gain if duplicate-related code were removed. Examines backend request paths, query patterns, and frontend bootstrap/render paths to estimate the practical impact.

**[DUPLICATE_PREVIEW_DEBUGGING.md](DUPLICATE_PREVIEW_DEBUGGING.md)** — A debugging guide for comparing duplicate-group state before and after using the "Min Score Preview" feature. Explains how to verify that preview is not persisting duplicate-review state, and what correct preview behavior looks like.

**[DUPLICATE_ROLE_DATA_FLOW.md](DUPLICATE_ROLE_DATA_FLOW.md)** — Documents how `Keeper` / `Duplicate` role values flow from MongoDB to the Inspector's "Duplicate Role" field, clarifying whether those values are enums or derived programmatically. Covers all duplicate/similarity-related values and their data flow from storage to the UI.

**[DUPLICATE_UI.md](DUPLICATE_UI.md)** — Describes the two main duplicate review surfaces in Tedography (the main app and the separate duplicate-review web app), explaining what each screen does, how they relate to each other, and what the visible duplicate states mean.

**[EDIT_QUEUE.md](EDIT_QUEUE.md)** — Documents the Edit Queue workflow for exporting original photos to an external folder, editing them in any tool, and importing the edited results back into Tedography. Covers setup, the export and import steps, and how imported files inherit metadata (album memberships, keywords, location, capture date) from their sources.

**[IMPLEMENTATION_GAPS.md](IMPLEMENTATION_GAPS.md)** — A comparison of Tedography's existing documentation and plans against the current code, identifying features that are described or planned but not yet implemented. Items are ordered by estimated practical value.

**[IMPORT_BROWSE_AND_SCAN_MANUAL_TESTS.md](IMPORT_BROWSE_AND_SCAN_MANUAL_TESTS.md)** — A manual API testing guide for the v1 import flow, with step-by-step `curl` commands covering the storage-roots, browse, scan, and register endpoints, as well as the three media routes (thumbnail, display, original).

**[KEYWORDS_USAGE_GUIDE.md](KEYWORDS_USAGE_GUIDE.md)** — A user-facing guide explaining how keywords work in Tedography, covering what they are for, how to create and organize them into a hierarchy, how to rename them, and how to assign them to photos.

**[MEDIA_ROUTES_MANUAL_TEST.md](MEDIA_ROUTES_MANUAL_TEST.md)** — Brief instructions for manually verifying that the media API routes (thumbnail, display, original) return correct HTTP cache headers, using `curl -I` against a running API server.

**[MULTIUSER_CHANGES.md](MULTIUSER_CHANGES.md)** — Documents the user-visible changes introduced by the multi-user RBAC implementation, organized by audience (admin vs. regular user). Includes a feature permission reference showing which operations are restricted to which roles.

**[PEOPLE_BROWSE.md](PEOPLE_BROWSE.md)** — Describes the dedicated People browse page at `/people`, its purpose as a proper browse surface for all known people, and how it fits into the overall People feature set without requiring the full Person Detail experience.

**[PEOPLE_DEV_HARNESS.md](PEOPLE_DEV_HARNESS.md)** — Documents the dev-only People Pipeline test harness at `/people/dev`, which provides a UI for exercising the People Pipeline (detecting faces, running matches, reviewing results) without needing manual `curl` commands during development.

**[PEOPLE_ENROLLMENT.md](PEOPLE_ENROLLMENT.md)** — Explains the enrollment and face-example management system for improving recognition quality over time, distinguishing between confirmed detections, reference face examples, and the enrollment workflow that links them to a `Person` record.

**[PEOPLE_MAINTENANCE.md](PEOPLE_MAINTENANCE.md)** — Describes the People Maintenance tools for keeping person data accurate over time, including a scoped maintenance workflow that lets you work through a targeted subset of the archive rather than reprocessing the entire library.

**[PEOPLE_PIPELINE_REKOGNITION.md](PEOPLE_PIPELINE_REKOGNITION.md)** — Explains how Amazon Rekognition was added as the first real face-recognition engine behind Tedography's provider-neutral pipeline adapter interface. Covers the three supported engine modes (`mock`, `rekognition`, `none`) and what the Rekognition pass changed in the codebase.

**[PEOPLE_PIPELINE_V1.md](PEOPLE_PIPELINE_V1.md)** — Describes the initial People Pipeline design and implementation, including the `Person`, `FaceDetection`, and `FaceMatchReview` collections, how derived `mediaAsset.people` entries are written only from confirmed detections, and the pluggable engine interface with `mock` and `none` adapters.

**[PEOPLE_PIPELINE_V1_IMPLEMENTATION_SUMMARY.md](PEOPLE_PIPELINE_V1_IMPLEMENTATION_SUMMARY.md)** — A changelog-style summary of what changed across domain, API, and web app when People Pipeline v1 was implemented — covering new collections, Mongoose models, routes, Redux slices, and UI components that were added.

**[PEOPLE_PIPELINE_VALIDATION.md](PEOPLE_PIPELINE_VALIDATION.md)** — Outlines the workflow for validating the real Rekognition-backed pipeline on a small curated corpus of photos, with goals focused on verifying detection consistency and understanding why specific faces might be ignored or skipped.

**[PEOPLE_RECOGNITION_RUN_SUMMARY.md](PEOPLE_RECOGNITION_RUN_SUMMARY.md)** — Documents the People Recognition Run Summary dialog that appears automatically after running face recognition, explaining when it opens, what breakdown it shows (detections, matches, skips), and what direct review actions it surfaces.

**[PEOPLE_REVIEW_UI.md](PEOPLE_REVIEW_UI.md)** — Describes the internal people-review workbench at `/people/review`, an admin-like surface for validating the People Pipeline backend in real usage. Explains its intentionally minimal scope as an early-phase validation tool before a fuller person-management experience is added.

**[PEOPLE_SEARCH.md](PEOPLE_SEARCH.md)** — Explains the People section in Tedography Search, covering the two concepts it supports: filtering by confirmed people metadata (derived `mediaAsset.people`) and filtering by unresolved face-review state. Documents how the two concepts differ and when each is useful.

**[PEOPLE_USAGE_GUIDE.md](PEOPLE_USAGE_GUIDE.md)** — A user-facing reference guide explaining what the People features are for, how face detection and recognition flow into confirmed people metadata on assets, and how to use People in day-to-day browsing and searching.

**[PERSON_DETAIL.md](PERSON_DETAIL.md)** — Documents the Person Detail page at `/people/:personId`, which gives each person a dedicated home in Tedography showing their confirmed photo appearances and face examples. Explains its scope as an early-phase page before a full person-management system is built.

**[SELECTION_ORDERING.md](SELECTION_ORDERING.md)** — Documents how `selectedAssetIds` order is established and maintained in the web app: single click sets `[assetId]`, Cmd/Ctrl-click appends to the end. Covers implications for loupe and slideshow navigation where order determines which asset is "first."

**[SMART_ALBUM_ORDER.md](SMART_ALBUM_ORDER.md)** — Describes Tedography's hybrid album-ordering model, where assets with a usable `captureDateTime` sort chronologically and assets without one can be manually ordered within an album using custom ordering modes (`Custom`, `Name`, `NumericThenName`).

**[TEDOGRAPHY_PEOPLE_REMAINING_ITEMS_EXPLAINED.md](TEDOGRAPHY_PEOPLE_REMAINING_ITEMS_EXPLAINED.md)** — Explains the remaining and partially complete items from the People roadmap not covered in the scoped-maintenance explanation. For each area it describes when you'd use it, what the UI would look like, why it matters, and what the consequences are of not having it.

**[TEDOGRAPHY_PEOPLE_ROADMAP_DONE_VS_REMAINING.md](TEDOGRAPHY_PEOPLE_ROADMAP_DONE_VS_REMAINING.md)** — A high-level status summary of the Tedography People roadmap, categorizing each major area as substantially complete, partially complete, or still open. Useful as a quick orientation before deciding what to work on next.

**[TEDOGRAPHY_PEOPLE_UI_ROADMAP.md](TEDOGRAPHY_PEOPLE_UI_ROADMAP.md)** — The staged UI roadmap for People features, guided by five principles (photo-first, confirmed-metadata-only, face tooling kept separate from asset metadata, incremental rollout). Defines each phase with its goals and deliverables.

**[TEDOGRAPHY_REPO_BOOTSTRAP.md](TEDOGRAPHY_REPO_BOOTSTRAP.md)** — Documents the initial repository bootstrap for Tedography — the project structure decisions, directory layout, and setup steps established at the start of the project by Ted Shaffer.

**[TEDOGRAPHY_SCOPED_MAINTENANCE_V3_EXPLANATION.md](TEDOGRAPHY_SCOPED_MAINTENANCE_V3_EXPLANATION.md)** — Explains four proposed "Broader Maintenance / Backfill Tools v3" features (reusable named scopes, background-style scoped jobs with progress, scope history / recent runs, and better scoped review continuity) in practical terms, covering what each would look like and why you'd want it.

**[THUMBNAIL_MAINTENANCE_MANUAL_TEST.md](THUMBNAIL_MAINTENANCE_MANUAL_TEST.md)** — A step-by-step manual testing guide for the thumbnail maintenance system, covering prerequisites, verify mode (checking integrity), repair mode (fixing missing thumbnails), and rebuild mode (regenerating all thumbnails).

**[agents.md](agents.md)** — Agent-specific instructions for automated coding tools (Codex, Claude, etc.) operating on the Tedography repository. Covers the architecture rules, dependency direction, import conventions, and what to check or avoid when making automated changes.

**[deep-research-report.md](deep-research-report.md)** — A research report comparing fasting plasma glucose vs. hemoglobin A1c as predictors of future type 2 diabetes, synthesizing findings from major cohort studies and systematic reviews. Note: this document is unrelated to Tedography and appears to have been accidentally placed here.

**[multiUserPermissionsRoadmap.md](multiUserPermissionsRoadmap.md)** — An informal phase-by-phase roadmap for adding multi-user RBAC to Tedography, starting with an authentication foundation (users collection, sessions, login/logout) and building up through role definitions, per-feature gating, and a user-management UI.

**[near-duplicate-detection-v1.md](near-duplicate-detection-v1.md)** — Describes a separate, iteration-friendly foundation for near-duplicate image analysis using perceptual descriptors, scoped to its own monorepo apps/packages. Intentionally kept out of the main review UI in v1 to avoid adding complexity before the approach is validated.

**[restructure.md](restructure.md)** — Documents the file-system restructuring steps for renaming storage paths from "Shafferography" to "Tedography," including the `mv` commands for moving directories on disk and the corresponding code and configuration changes required.

**[tedography_advanced_keyword_queries_spec.md](tedography_advanced_keyword_queries_spec.md)** — A proposed spec for advanced keyword query support in Search, covering AND/OR/NOT combinations and hierarchical keyword matching. Intended as a follow-on to the basic keyword roadmap once keyword storage and assignment are in place.

**[tedography_button_toggle_style_guide.md](tedography_button_toggle_style_guide.md)** — A style guide defining a consistent visual system for action buttons and toggle controls across the Tedography UI, aiming for a photo-first, compact, and predictable interface that distinguishes clearly between immediate actions and persistent toggle states.

**[tedography_slideshow_features.md](tedography_slideshow_features.md)** — A feature spec for a first-class slideshow mode in Tedography, covering playback controls (play/pause, next/prev, skip, speed, loop), transitions, and additional features layered on top of the original spec.

**[tedography_slideshow_features_original.md](tedography_slideshow_features_original.md)** — The original (unmodified) version of the slideshow feature spec, listing only the core playback controls, navigation, and transitions without any subsequent additions or revisions.
